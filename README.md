The simulation started out by creating a simple lava tube design in blender, adapting a free model that has now been removed from blendswap, and creating a simple rectangular prism to represent the rover. Following this, a physics based environment by converting the model into a collision mesh was created. This allowed for panda3D’s built in bullet physics to be added to green rays that shoot in all directions to collide with the walls of the lava tube to simulate LiDAR. The LiDAR uses raycasting to measure the distance between the rover and the walls. The location and distance of this collision is saved and used in the occupancy grid. The camera based SLAM uses a similar method, as to simplify the simulation, the rays are cast just in the front of the rover instead of the full 360 degrees. The information received from either one of these is put in its own occupancy grid and classified as unknown, free, or occupied, and this allows maps, frontier detection, and A* path finding to be relatively simple.
The frontiers for this simulation are chosen by checking for unknown areas that move the rover into an area with the most unknowns. Previously visited areas, walls, and mostly revealed areas are avoided to ensure maximum progress in the SLAM map. Once the frontier location is chosen, the A* Path planning actually calculates the route the rover needs to travel, looking through the occupancy grid to find the shortest route that is unobstructed. Continuing this process, sequences of grid coordinates are output from frontier to frontier. To summarize the steps: sense → map → select frontier → plan path → move → sense again.
